## 1. 데이터셋 확정 — YelpZip

| 역할 | 데이터셋 | 규모 | 텍스트 | 상태 |
|---|---|---|---|---|
| **주 실험** | **YelpZip** | 608,458건 | ✅ | 확보 |
| 재현성 검증 | YelpChi `.mat` | 45,954건 | ❌ | 확보 |

### 전환 이유

선행연구가 공통 사용하는 YelpChi 공개 배포판(`YelpChi.mat`)에는 **리뷰 원문이 없습니다**
(32차원 행동 피처와 인접행렬만 존재). 3개 배포처 파일의 MD5가 동일함을 확인했으며,
공개 경로로는 원문 판을 구할 수 없었습니다. 원저자(Rayana & Akoglu)께 원문을 요청했으나
회신을 받지 못해, **동일 저자가 같은 방식으로 수집한 YelpZip**을 주 데이터셋으로 사용합니다.
YelpZip은 Shehnepoor et al. 서베이에 대표 Yelp 데이터로 등재되어 있으며, 확보 파일의
실측치(608,458건 / 260,239 유저 / 5,044 업체)가 서베이 수치와 업체 수 기준 정확히 일치합니다.

### 컬럼 구성

| 컬럼 | 의미 | 비고 |
|---|---|---|
| `user_id` | 작성자 ID | 그래프 연결용 (모델 피처로 사용 금지) |
| `prod_id` | 업체 ID | 그래프 연결용 |
| `rating` | 별점 (1~5) | |
| `label` | 정답 | **−1 = 사기, 1 = 정상** (부호 주의) |
| `date` | 작성일 | 2004~2015, **일 단위** (시:분 없음) |
| `text` | 리뷰 원문 | 평균 629자, 결측 0 |

## 2. 전처리 원칙 (데이터 무결성)

세 가지 원칙을 파이프라인 전반에 적용했습니다.

1. **행 순서 보존**: 텍스트 임베딩(`.npy`)에는 ID가 없어 행 순서가 유일한 정합 수단입니다.
   `review_id`(0..N−1)를 기준으로 모든 산출물을 정렬하며 재정렬을 금지합니다.
2. **`user_id`/`prod_id`를 모델 피처로 사용 금지**: 익명화·정렬 순서의 부산물로
   `user_id` 크기만으로 사기율이 5배 차이나므로(실제 신호 아님), 그래프 연결에만 사용합니다.
3. **라벨·피처는 전체 데이터에서 계산**: 부분 표본에서 계산하면 값이 왜곡됩니다
   (업체 400개 표본 실험에서 신규계정형 라벨의 39.8%가 거짓으로 확인). 라벨·수작업 피처는
   전체 608K에서 계산하고, 그래프와 학습만 표본에서 수행합니다.

## 3. 사기 유형 서브라벨링 (규칙 기반)

데이터에 유형 라벨이 없으므로, 사기 유형 분류의 뿌리 논문 Jindal & Liu(2008)의 문제의식
("리뷰 사기는 단일 범주가 아닌 여러 패턴으로 나타난다")에서 출발하여 규칙 기반으로 하위
라벨링했습니다. 실제 정의와 임계값은 각 특화 연구를 근거로 삼았습니다.

### 3.1 신규계정형 (New-account)

- **정의**: 작성자의 총 리뷰 수 ≤ 3
- **근거**: cold-start 계열 연구(Li et al. 2019; SATURN, Da et al. 2019). 계정 생성일 컬럼이
  없으므로 "가입 후 N일"이 아니라 "작성자 총 리뷰 수"로 조작적 정의(operational definition).
  Yelp 데이터에서 "리뷰 수가 적은 유저 = 신규 유저"는 학계 표준 처리 방식입니다.

### 3.2 버스트형 (Burst) — 재정의 (§4에서 상술)

- **정의**: 같은 상점 7일 내 3건 이상 + 극단평점(1/5점) + 상점 평균 대비 평점이탈 > 1.5
- **근거**: Fei et al.(2013)

### 3.3 믹스형 (Mixed)

- **정의**: 신규계정형 ∩ 버스트형 (두 조건 동시 만족)

### 3.4 최종 유형 분포 (전체 608,458건, 전체 사기율 13.22%)

| 유형 | 표본 수 | 사기율 | 전체 평균 대비 |
|---|---|---|---|
| 신규계정형 | 302,070 | 23.0% | ×1.7 |
| 버스트형 | 19,077 | 28.1% | ×2.1 |
| 믹스형 | 14,046 | 35.8% | ×2.7 |

세 유형 모두 전체 평균의 1.7~2.7배로 유형 특성이 뚜렷합니다. 믹스형(35.8%)이 가장 높아,
두 사기 패턴이 겹칠 때 사기 확률이 가장 크다는 점이 드러납니다.

### 3.5 유형 간 겹침 처리 방침

버스트형 사기의 74%가 신규계정형과 겹칩니다(믹스형 14,046건). 세 유형을 상호배타적으로
나누면 순수 버스트형의 표본·사기율이 급감하므로(5,031건, 6.6%), **겹침을 허용한 독립
라벨로 정의**하고 각 유형별 탐지 실험을 독립적으로 수행합니다. 각 실험은 자기 유형 데이터
안에서 정상 vs 사기를 구분하므로 겹침이 실험에 영향을 주지 않습니다.

## 4. 버스트형 재정의 (교수님 지적 반영)

### 4.1 배경 — 기존 임시 라벨의 문제

초기 버스트 라벨은 전역 고정 임계값(7일/5건)이었으며, 예비 분석에서 **윈도우 3·7·14일 ×
임계 3·5·10건의 9개 조합 중 8개**에서 버스트 구간의 사기율이 전체 평균을 **하회**했습니다
(배율 0.87~1.15). 즉 리뷰 급증이 조직적 사기가 아니라 정상적 인기 상승을 반영한 것으로,
이는 Fei et al.(2013)이 지적한 "버스트는 인기 상승일 수도, 사기일 수도 있다"는 문제와
정확히 일치합니다.

### 4.2 데이터 진단 — 시간 집중만으로는 사기가 드러나지 않음

전역 임계값이 실패하는 이유를 데이터로 확인했습니다.

| 시간 집중 기준 | 사기율 |
|---|---|
| 1일 내 5건 이상 | 10.00% (전체 평균 이하) |
| 3일 내 5건 이상 | 11.25% (전체 평균 이하) |
| 7일 내 10건 이상 | 12.38% (전체 평균 이하) |

YelpZip 식당 리뷰에서는 단순 시간 집중이 대부분 정상 인기 상승을 반영하며, 사기와 약하게만
연관됩니다.

### 4.3 재설계 — Fei et al.(2013) 방식: 버스트 + 평점 조작 신호 결합

Fei 논문은 버스트를 최종 판정이 아니라 의심 구간으로 보고, 추가 신호로 사기를 걸러냅니다.
이 방식을 따라 버스트에 평점 조작 신호를 결합했습니다.

**버스트형 정의:**
1. 버스트 — 같은 상점 7일 내 3건 이상 (시간 집중)
2. 극단평점 — 평점이 1점 또는 5점 (홍보/비방)
3. 평점이탈 — 상점 평균 평점에서 1.5 이상 벗어남 (Fei의 Rating Deviation)

**파라미터 탐색 결과** (신규계정 신호는 제외하여 신규계정형과의 중복 배제):

| 조합 | 표본 수 | 사기율 |
|---|---|---|
| 버스트만 (7일 3건) | 다수 | ~13% (실패) |
| **7일 3건 + 극단 + 이탈>1.5** | **19,077** | **28.11%** (채택) |
| 같은평점 5 + 극단 + 이탈>1.5 | 954 | 48.7% (표본 부족) |

사기율 30% 이상 조합은 표본이 3,000건 이하로 떨어져 학습이 불안정하므로,
**사기율 28.1% · 표본 19,077건**을 최적 균형점으로 채택했습니다.

### 4.4 재정의 효과

| 라벨 | 표본 수 | 사기율 |
|---|---|---|
| 임시 버스트 (전역 임계값) | 275,290 | 11.62% |
| **재정의 버스트 (Fei 방식)** | 19,077 | **28.11%** |

버스트 구간 사기율이 전체 평균 이하(11.6%)에서 전체 평균의 2.1배(28.1%)로 개선되었습니다.

### 4.5 명칭에 관한 유의

본 버스트형은 순수 시간 버스트가 아니라 **시간 집중 + 평점 조작을 결합한 정의**입니다.
YelpZip에서 순수 시간 버스트가 사기와 약하게만 연관되기 때문이며, 이는 Fei et al.(2013)의
방법론을 데이터 특성에 맞게 적용한 결과입니다. 최종 보고 시 "버스트+평점조작(coordinated
burst)"임을 명시할 예정입니다.

## 5. 수작업 피처 (조건 A 입력)

YelpChi `.mat`의 32차원 피처는 YelpZip에 없으므로, Rayana & Akoglu(2015) 계열 피처를
전체 608,458행에서 직접 재계산했습니다(소요 4.3분).

### 총 38개 = 행동 25개 + 텍스트 파생 13개 (34%)

| 수준 | 개수 | 내용 |
|---|---|---|
| 리뷰 | 12 | 행동 5개(extremity, rating_deviation, deviated_rating, early_time, singleton) + 텍스트 7개(대문자 비율, 길이, 1인칭대명사, 느낌표, 주관/객관 비율) |
| 작성자 | 13 | 일·월별 최대 리뷰수, 긍/부정 비율, 평균·표준편차 평점, 평점 엔트로피, 시간간격 엔트로피, 내용 유사도, 평균 평점편차·리뷰 길이 |
| 업체 | 13 | 작성자와 동일 구조 |

**9/2 미팅 지적에 대한 답**: 38개 중 13개(34%)가 텍스트 파생 통계입니다. 즉 "구조/메타데이터
기반"인 조건 A도 텍스트 정보를 이미 사용하나, 모두 표층 통계(길이·대문자 비율·n-gram 유사도
등)이며 의미 정보는 담지 않습니다. **따라서 조건 A와 B의 차이는 "텍스트를 쓰느냐"가 아니라
"표층 통계로 주느냐, 고차원 의미 임베딩으로 주느냐"입니다.**

### 참조 구현(FraudSquad)의 버그 수정

공개 코드의 피처 계산 함수를 참조하되, 다음 4개 버그를 수정하여 원 논문 방식에 맞췄습니다.

- `avg_rating`/`rating_std` 자리에 내용 유사도를 덮어써 두 피처가 손실되던 문제
- 업체 루프에서 직전 작성자의 bigram 행렬을 참조하던 문제
- 평점 엔트로피를 range(0~4)로 계산해 5점을 누락하던 문제
- 느낌표 비율이 분할 방식 오류로 항상 0이 되던 문제 (수정 후 리뷰 40%가 0이 아님)

## 6. 예비 실험 — 조건 A(수작업) vs C(텍스트)

작성자 단위 분할, 25% 표본, 로지스틱 회귀(선형 프로브) 기준 **AUROC**:

| 유형 | 수작업 38개 | 텍스트 임베딩 384 | 격차 (A−C) |
|---|---|---|---|
| 신규계정형 | 0.705 | 0.658 | +0.047 |
| 믹스형 | 0.681 | 0.661 | +0.020 |
| 버스트형 | 0.893 | 0.710 | +0.183 |
| 일반 | 0.887 | 0.732 | +0.155 |
| 전체 | 0.825 | 0.712 | +0.113 |

**수작업 피처가 전반적으로 우수하나, 격차가 유형마다 크게 다릅니다.** 버스트형·일반에서는
격차가 0.15~0.18인 반면, 신규계정형·믹스형에서는 0.02~0.05로 줄어듭니다. 신규계정형에서
행동 이력이 빈약해 구조·메타 정보의 우위가 작아진다는 작업 가설과 방향이 일치합니다.

**해석 시 유의사항**: PR-AUC는 기저선이 층별 사기율(3.2~26.0%, 8배 차이)이므로 층 간 직접
비교가 불가하며, **AUROC 또는 기저선 대비 lift를 병기**해야 합니다. 최종 실험에서 평가
지표를 통일할 예정입니다.

**한계**: (1) 아직 그래프를 쓰지 않은 선형 프로브이며, 조건 A의 정의는 "그래프 + 수작업"이므로
GNN 적용 시 결과가 달라질 수 있습니다. (2) `singleton` 피처가 신규계정형 정의와 겹쳐 해당
층에 일부 라벨 누수가 있어, 최종 실험에서는 유형 정의에 쓰인 변수를 제외한 버전을 병행
보고합니다. (3) 단일 분할·단일 시드, 선형 모델 기준입니다.

## 7. 실험 설계 (확정)

교수님 피드백에 따라 비교 축을 노드 피처 구성으로 재정의하고, 3×3 매트릭스로 구성합니다.

| 노드 피처 \ 사기 유형 | 신규계정형 | 버스트형 | 믹스형 |
|---|---|---|---|
| ① 구조/메타 + 수작업 (GNN) | | | |
| ② 하이브리드: 구조 + 텍스트 임베딩 (GNN) | | | |
| ③ 텍스트 전용 (MLP, non-GNN) | | | |

- **③ 텍스트 전용을 MLP로 구현**: 그래프에 텍스트 임베딩만 넣고 구조를 배제하는 조합은
  GNN을 쓸 명분이 없어 성립하지 않으므로, 텍스트 단독 성능은 MLP로 측정합니다. 이는 "이
  유형은 구조가 필요한가, 텍스트만으로 충분한가"를 각 셀에서 논증하기 위한 필수 대조군입니다.
- **GNN 백본**: CARE-GNN은 강화학습 기반이라 성능 저하 원인 분석이 어려워 제외하고,
  바닐라 GNN(GCN/GraphSAGE)으로 기준선을 확보한 뒤 PC-GNN(클래스 불균형 보정),
  BWGNN(주파수 보정)을 단계적으로 적용합니다.
- **차원 불균형**: 텍스트 임베딩(384)과 수작업 피처(38)의 차원 격차가 크므로, 하이브리드는
  블록별 표준화 또는 PCA 축소 버전을 병행 보고합니다.

## 9. 남은 작업

- **그래프 구성**: R-U-R / R-S-R / R-T-R 인접행렬 생성 (작성자 단위 표본 기준)
- **모델 구현**: GCN/GraphSAGE(구조·하이브리드) + MLP(텍스트)
- **본 실험**: 3×3 매트릭스 채우기, 유형별 평가지표(AUROC/lift) 통일
- **라벨 누수 처리**: 각 유형 실험에서 유형 정의에 쓰인 피처 제외 버전 병행
- **PC-GNN/BWGNN 확장**: 저사기율 층(버스트·일반) 성능 보완

## 부록: 환경 제약

- **DGL은 Python 3.13+ 미지원**입니다. FraudSquad 등 공개 구현이 DGL 의존이라 그대로
  실행되지 않으므로, 그래프는 `scipy.sparse`로 구성하고 모델은 `torch`/`torch-geometric`으로
  구현합니다.
- 텍스트 임베딩은 전부 로컬 연산(API·토큰 소비 없음)이며, 결정론적이라 재생성 가능합니다.
