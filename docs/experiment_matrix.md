# 실험 매트릭스 (조건 A/B/C × 사기 유형)

> 9/2 피드백([`meeting_notes/2026-09-02_professor_feedback.md`](meeting_notes/2026-09-02_professor_feedback.md)) 반영. 목표·배경은 [`project_plan.md`](project_plan.md), 라벨링 상세는 [`progress_reports/전처리_progress_report.md`](progress_reports/전처리_progress_report.md) 참고. 이 문서는 실행 순서·상태만 추적하는 용도.

## Phase 1 — 데이터셋 확정 및 스키마 검증

**목표**: 텍스트 포함 YelpZip을 데이터셋으로 채택하고, 리뷰-업체-작성자 관계가 그래프로 매핑 가능한지 검증한 뒤, **조건 A/B가 공유할 그래프 구성 방식을 하나로 확정**한다.

**방법**:

1. **라벨 분포 확인**: 사기/정상 라벨 비율, 전체 클래스 불균형 정도를 먼저 파악.
2. **그룹핑 가능성 검증**: reviewer_id / product_id로 실제 관계 엣지를 구성할 수 있는지 확인 — 해당 컬럼의 존재 여부, 결측치, 그룹 크기 분포(예: 작성자당 평균 리뷰 수) 점검.
3. **관계별 라벨 동질성 측정**: R-U-R(동일 작성자) / R-S-R(동일 상점) / R-T-R(동일 시점) 각각에 대해, 같은 엣지로 연결된 두 리뷰의 라벨이 실제로 상관이 있는지 측정.
4. **그래프 구성 후보 설계** (조건별로 다르게 고르는 게 아니라, A/B가 공유할 단일 후보군):
   - 후보 ①: 동질성 높은 관계만 엣지로 사용
   - 후보 ②: 동질성 낮은 관계는 엣지 대신 그 관계에서 파생된 집계 통계를 노드 피처로 흡수
   - 후보 ③: 이종 그래프(R-GCN/HAN 등)로 관계 타입별 가중치를 모델이 학습하게 함
5. **후보 비교는 조건 A만으로 수행**: 조건 A가 실행 우선순위 1번이라 가장 먼저 도니, 이걸 테스트베드 삼아 후보 ①~③ 중 어느 그래프 구성이 나은지 비교하고 하나로 확정한다. (조건 B로 후보를 나눠 비교하지 않는다 — 그러면 A/B 비교 자체가 오염됨)
6. **확정된 그래프 구성을 B에 그대로 재사용**: 그래프 구조(엣지셋·가중치·관계 처리 방식)는 A/B 간 고정. 노드 피처(수작업 vs 텍스트 임베딩)만 달라지도록 유지.
7. C는 그래프를 아예 쓰지 않는 게 설계 의도이므로 이 단계와 무관 — 그대로 진행.

**산출물**: 데이터셋 채택 근거, 관계별 라벨 동질성 결과표, 확정된 그래프 구성 방식 1건(A/B 공통 적용 대상).

> **핵심 원칙**: 그래프 구성 방식을 탐색하는 실험과, A vs B 매트릭스 비교 실험은 분리한다 — 전자는 A만으로 먼저 끝내고, 후자는 그 결과를 고정값으로 물려받는다. 매트릭스 비교의 유일한 변수는 "노드 피처 종류"여야 하므로, 그래프 구조를 조건별로 다르게 실험하면 A vs B 비교 자체가 무의미해진다.

**후보 비교 결과 (2026-09-09) — 후보 ① 확정**: 후보 ①(R-U-R만) vs 세 관계(R-U-R+R-S-R+R-T-R union)를 조건 A(Rayana `review_16_only`/`all_38` 피처, 신규계정형·혼합·버스트형)로 비교한 결과, 세 관계 그래프가 모든 조합에서 GNN 절대 AUROC가 낮았다(버스트형 −0.19~−0.20, 최대 낙폭). 공식 YelpChi(.mat) 비교(0.9166→0.6452)와 방향이 일치. 따라서 **후보 ① R-U-R만 사용**을 그래프 구성으로 확정한다. 상세 수치·표본 조건은 [`../results/feature_ablation/three_relations.json`](../results/feature_ablation/three_relations.json) 참고(신규계정형은 작성자 15% 서브샘플, 혼합·버스트형은 전량; 일반 유형은 우선순위 밖이라 미실행).

## Phase 2 — 사기 서브유형 라벨링 (신규계정형 → 버스트형 순)

**목표**: 조건 A/B/C가 유형별로 나눠 돌아가야 하므로, 그 전에 각 리뷰의 사기 유형 라벨을 확정한다.

**2-1. 신규계정형 — ✅ 확정**
- 방법: "해당 작성자의 전체 리뷰 수 ≤ 임계값"으로 정의. 리뷰 수 계산은 반드시 표본화 이전 **전체 데이터 기준**으로 해야 함(표본 기준으로 세면 리뷰 수가 과소집계되어 오염됨).

**2-2. 버스트형 — 🔶 진행 중 · 미확정**

| 단계 | 시도 | 결과 | 판정 |
|---|---|---|---|
| 1 | 교수님 지시 이행: 상점별 KDE(밀도 상위 5%)로 버스트 구간 정의 | 사기율 13.9% ≈ 전체 평균(13.22%) | 실패 — 순수 시간 밀도는 정상적 인기 상승과 구분 안 됨(Fei et al. 2013이 지적한 문제와 일치) |
| 2 | 1단계 결과 + 평점조작 신호(극단평점 1/5점, 상점평균 대비 평점이탈) 결합 | 사기율 31%, 표본 2,623건 | 판별력은 확보했으나 표본 부족 — 이후 작성자 표본화(예: 7.5%)까지 거치면 200건 미만으로 GNN 학습 불가 수준까지 줄어들 것으로 예상 |
| 3 | 시간축을 상점별 KDE에서 전역 윈도우(예: 7일 3건)로 완화 | — | 절충 시도. 교수님이 지양하라던 "전역 고정 임계값" 방향으로 일부 되돌아간 것이므로 사유를 투명하게 명시해야 함(표본 크기 제약) |
| 4 (현재 후보) | 완화된 시간 기준 + 평점 신호 결합 | 사기율 28.1%, 표본 19,077건 | 2단계 대비 표본 약 7배 확보, 사기율은 소폭 하락 — 절충점으로 유력하나 **아직 최종 확정 아님** |

**미확정 사유 — 확정 전 확인 필요한 항목**:
- 19,077건 층이 최종 작성자 표본화(예: 7.5%) 이후에도 학습 가능한 규모로 남는지 재확인.
- 시간축 완화가 1단계에서 확인된 문제(정상 인기 상승 오염)를 다시 불러들이는 건 아닌지 — 완화된 정의로 잡힌 사례 일부를 직접 확인해 검증.
- 다른 완화 폭(예: 5일 2건, 10일 4건 등)도 시도해 사기율-표본크기 트레이드오프를 몇 개 더 비교한 뒤 "이게 최선의 균형점"이라는 근거 보강 여부.

**2-3. 신규&버스트 교집합(혼합)**
- 방법: 신규계정형 ∩ 버스트형 겹침을 허용. 표본이 부족하면 "일반"으로 통합. (버스트형이 미확정이므로 이 항목도 함께 미확정)

**라벨 누수 방지**: 서브유형 정의에 쓰인 변수(리뷰 수, singleton 여부 등)가 조건 A의 수작업 피처에 그대로 들어가지 않도록, 해당 변수를 제외한 버전을 병행 준비.

## 판단 기준 — 언제 "MLP→GNN 개선폭(delta)"을 보고, 언제 "GNN 절대 성능"을 보는가

이 매트릭스 작업 중 반복적으로 나오는 선택 상황(그래프 구성, 피처 구성 등)마다 어느 기준으로 비교할지 헷갈릴 수 있어 원칙을 정리한다. **기준은 "그 대상이 무엇이냐"에 따라 갈린다.**

- **그 대상이 매트릭스에서 비교하려는 독립변수 자체라면 → delta(MLP→GNN 개선폭) 기준.** 이 연구의 RQ가 "구조 정보가 유형별로 얼마나 기여하는가"이므로, 절대 성능만 보면 "피처 자체가 원래 잘 맞혔다"와 "그래프가 실제로 기여했다"가 섞인다. 예: 조건 A의 피처 구성(review_16_only vs all_38)이 여기 해당 — 그룹 상수 피처(작성자/업체 수준)를 넣으면 MLP 절대 성능은 올라가지만, 이는 그래프의 기여가 아니라 피처 테이블에 그룹 정보가 새어 들어간 것에 가깝다. 유형별 구조 의존도 차이가 review_16_only에서만 뚜렷이 드러난 것이 이 기준을 따라야 하는 이유를 실증한다.
- **그 대상이 매트릭스 전체에 공통으로 깔리는 인프라(고정값)라면 → GNN 절대 성능 기준.** Phase 1의 그래프 구성(R-U-R만 vs 세 관계)이 여기 해당 — 이건 A/B 조건 양쪽에 동일하게 적용될 바닥판이지 비교 대상 자체가 아니므로, "이 그래프를 썼을 때 GNN이 실제로 얼마나 잘 맞히는가"로 최선의 바닥판을 고르면 된다. 실제로 이번 비교(세 관계 vs R-U-R)는 두 기준이 같은 결론(R-U-R 확정)을 가리켰다.

| 조건 | 그래프 구조 | 노드 피처 | 모델 |
|---|---|---|---|
| A. 구조/메타데이터 기반 | 사용 (Phase 1에서 확정된 구성) | 수작업 표층 피처 (38차원) | 바닐라 GNN(GCN/GraphSAGE) → PC-GNN → (여유 시) BWGNN |

| C. 텍스트 전용 | 미사용 | 텍스트 임베딩만 | MLP (non-GNN, 순수 베이스라인) |

## 유형 정의 (행)

- **신규계정형**: 작성자 전체 리뷰 수 ≤ 임계값. 전체 데이터 기준으로 계산(표본 기준 계산 시 오탐 39.8% 확인됨).
- **버스트형** (🔶 미확정, 상세는 Phase 2 참고): 현재 후보는 전역 윈도우(7일 3건) + 극단평점(1/5점) + 평점이탈 > 1.5 (Fei et al. 2013 방식), 사기율 28.1%·표본 19,077건. 상점별 KDE 단독 정의는 사기 판별력 없음(13.9% ≈ 전체 평균)이라 폐기.
- **신규&버스트 교집합(혼합)**: 두 조건 동시 만족. 표본이 부족하면 "일반"으로 통합.

## 실행 우선순위

축소 우선순위: 유형은 **신규계정형 → 버스트형 → 신규&버스트 교집합** 순, 조건은 각 유형 안에서 **A → C → B** 순(A는 이미 검증된 순수 구조 기준선, C는 구현이 가장 간단한 대조군, B는 구현 난이도가 가장 높은 결합 조건이라 마지막). 시간이 부족하면 교집합 행(우선순위 7~9)은 생략하고 2×3(우선순위 1~6)까지만 채워도 최소 목표 달성.

|---|---|---|---|---|

## 공통 유의사항

- 셀마다 라벨 정의에 쓰인 변수(`singleton` 등)를 제외한 버전을 병행 보고해 라벨 누수를 점검한다.
- 사기율이 유형별로 크게 다르므로(3~26%) AUROC/AUPRC와 함께 베이스라인 대비 lift를 병기한다.
