## 연구 질문 재확인 (9/9)

- 이 연구의 기여점은 "어떤 모델/조합이 최고 점수를 냈는가"가 아니라 **"정보를 추가했을 때의 효과(정보 추가 효과)"**를 밝히는 것. 새 모델 개발이나 SOTA 경쟁이 목적이 아님.
- **실험 순서**: ① 수작업 피처만 → MLP → ② 같은 피처를 바닐라 GNN에 (PC-GNN 등으로 조기에 넘어가지 말 것) → ③ 같은 구조에 텍스트 임베딩을 노드 피처로 추가 → ④ 상점 메타데이터 추가. **③·④는 반드시 각각 독립적으로 추가해 효과를 분리**할 것(동시에 묶으면 개선 원인이 임베딩인지 메타데이터인지 구분 불가).
- **평가 기준**: "어떤 모형이 최고 점수를 얻었는가"가 아니라 "그래프(관계)를 추가했을 때 어떤 사기 유형에서 더 도움이 되었는가"를 기준으로 설계·해석. 아래 "판단 기준" 절(delta vs 절대 성능)과 같은 방향이므로 그대로 유지.

## 용어 주의 — Yelp 라벨은 "사기"가 아니라 "니어 그라운드 트루스" (9/9)

Yelp 필터링 라벨은 "이 리뷰가 사기다"라는 확정된 사실이 아니라 Yelp 자체 필터링 로직에 의해 걸러진 결과일 뿐. 보고서·논문에서 근거를 대며 "사기다"라고 단정하는 워딩은 금지 — 항상 **"Yelp가 제공한 필터링 정보원에 의거하여"**라는 식으로 표현할 것.

## Phase 1 — 데이터셋 확정 및 스키마 검증

**목표**: 텍스트 포함 YelpZip을 데이터셋으로 채택하고, 리뷰-업체-작성자 관계가 그래프로 매핑 가능한지 검증한다.

**방법**:

1. **라벨 분포 확인**: 사기/정상 라벨 비율, 전체 클래스 불균형 정도를 먼저 파악.
2. **그룹핑 가능성 검증**: reviewer_id / product_id로 실제 관계 엣지를 구성할 수 있는지 확인 — 해당 컬럼의 존재 여부, 결측치, 그룹 크기 분포(예: 작성자당 평균 리뷰 수) 점검.
3. **관계별 라벨 동질성 측정**: R-U-R(동일 작성자) / R-S-R(동일 상점) / R-T-R(동일 시점) 각각에 대해, 같은 엣지로 연결된 두 리뷰의 라벨이 실제로 상관이 있는지 측정.

> **9/9 갱신 — 아래 4~7번(단일 그래프 구성 후보를 조기 확정해 A/B에 고정 적용) 절차는 폐기, 7가지 관계 조합 실험으로 대체**: 교수님 지적("라벨 동질성이 낮다고 정보가 없는 게 아니고, 동질성이 높다고 성능이 높은 것도 아님 — 이 연구는 SOTA 경쟁이 아니라 프로브(probe) 성격")에 따라, "가장 성능 좋은 후보 하나"를 조기 확정하지 않고 **RUR/RSR/RTR을 유형별로 7가지 조합 모두 실험**해 관계 추가의 시너지를 관찰하는 방식으로 바꿈. 상세는 아래 "Phase 1-B" 절 참고.

## Phase 1-B — 그래프 관계 조합 실험 설계 (RUR/RSR/RTR 7가지 조합, 9/9 확정)

**배경**: 저활동형(구 신규계정형)은 리뷰 수 ≤3 기준으로 자르면 싱글턴(리뷰 1건, R-U-R 엣지 없음) 비율이 약 **69%**에 달해, R-U-R만 쓰면 그래프/GNN이 사실상 무의미해짐. 교수님: "R-U-R 하나에만 의존하지 말고 R-S-R, R-T-R 등 다른 관계로 이 공백을 어떻게 보완할 수 있는지를 보라."

**방법**: RUR·RSR·RTR은 데이터셋에 이미 정의되어 있어 추가 전처리 불필요. 아래 7가지 조합을 유형별로 모두 실험한다.

| # | 조합 |
|---|---|
| 1 | RUR 단독 |
| 2 | RSR 단독 |
| 3 | RTR 단독 |
| 4 | RUR + RSR |
| 5 | RUR + RTR |
| 6 | RSR + RTR |
| 7 | RUR + RSR + RTR (전체) |

- 목적: 관계를 추가했을 때 유형별로 시너지(개선 정도)가 얼마인지 관찰. **"차이가 없다"도 의미 있는 결과**로 취급(반드시 개선을 증명해야 하는 게 아님).
- 시간이 부족하면 조합 수를 줄일 수 있음(교수님이 명시적으로 시간 제약 언급).
- 특히 **저활동형**에서 RSR·RTR이 RUR의 고립 노드 공백을 어떻게 보완하는지가 핵심 관찰 포인트 — 저활동형과 버스트형은 관계 정보 필요성이 갈리는 대비 지점이라 이 자체가 해석 가능한 인사이트가 될 수 있음.

## Phase 1-C — 데이터 범위: 2014년 한 해로 한정 (9/9 확정)

**배경**: YelpZip 전체 608,458건(9/7 보고서 기준)을 그대로 쓰면 유형별 표본 편차가 크고 GNN 그래프 엣지 수가 과도해짐. 팀은 임의 샘플링(예: 5만 건)을 검토했으나 **교수님이 임의 샘플링을 금지**하고, 연구 목적에 맞는 필터링 기준을 요구.

**검토된 필터링 옵션**: ① 상점별 리뷰가 지나치게 적은 상점 제외, ② 업종 통일(전체의 약 80%가 식당), ③ 리뷰 작성 기간 좁히기(최종 채택).

**확정된 결정**: **2014년 리뷰만 사용**.
- 선정 근거: 전체 데이터(2004-10-20~2015-01-10) 중 2014년 비중이 약 **29.7%(≈18만 건)**로 전 기간 중 최다(직전 연도 약 21%, 2013년부터 누적 시 전체 절반, 2011년 이후 누적 약 80%). 2014년 내 월별 분포도 최소 약 1.1만~최대 약 1.7만 건으로 비교적 균등(다른 연도는 특정 월 쏠림 존재).
- "가장 데이터가 많은 최근 연도 + 월별로 고르게 분포"를 명분으로 보고서·논문에 명시할 것.

**미확정 — 후속 확인 필요**:
- 라벨·수작업 피처 계산 기준: ①전체 10년 이력으로 계산하되 학습·평가 대상만 2014년으로 한정 vs ②2014년 서브셋 자체로 라벨·피처 재계산 — 9/9 미팅에서 명시적으로 결정되지 않음. 팀 내부 정리 필요(9/7 보고서의 "라벨·피처는 전체 60만건에서 계산" 원칙과 이번 결정을 어떻게 결합할지가 핵심 쟁점).
- 업종(식당 한정 여부) 필터링 적용 여부 — 논의만 되고 결론 미확정.

## Phase 2 — 사기 서브유형 라벨링 (9/9 대폭 개정)

**목표**: 조건 A/B/C가 유형별로 나눠 돌아가야 하므로, 그 전에 각 리뷰의 사기 유형 라벨을 확정한다. **9/9부로 유형 간 라벨은 반드시 디스조인트(배타적)해야 함** — 9/7 보고서의 "중복 허용(독립 라벨)" 방식에서 변경. 우선순위는 **저활동형(신규) → 버스트형**을 먼저 집중 확정하고, 믹스형(중복 허용 시 발생하는 조합)은 나중으로 미룬다.

**2-1. 저활동형 (구 "신규계정형") — 🔶 명칭·정의 개정 필요 (9/9)**

- "총 리뷰 수 ≤ 3" 대체 정의 자체는 유지 가능(YelpZip에 계정 생성일 컬럼이 없어 콜드스타트 대리 지표로 문제없음) — 다만 **"신규"라는 워딩이 부정확**하므로 문서상 정의는 **"관측 이력이 적은 작성자(저활동형)"**로 명확히 할 것(팀 내부 호칭은 "신규" 유지 가능).
- **점 시점 제약(신규 요건, 9/9)**: 반드시 **해당 리뷰 작성 시점까지의 이력만으로** 판단해야 함 — 학습 시 미래 시점 데이터가 새어 들어가면 안 됨. 기존 구현이 "표본화 이전 전체 데이터 기준"으로 리뷰 수를 계산한다고만 명시되어 있어, 이 시점 제약(as-of 리뷰 작성 시각)을 만족하는지 **재확인 필요**.
- **고립 노드 문제**: 이 기준으로 자르면 싱글턴(R-U-R 엣지 없음) 비율이 약 **69%** — Phase 1-B의 7조합 실험으로 RSR/RTR 보완 여부를 확인.
- 상태: 임계값 로직 자체는 ✅ 확정이었으나, 명칭·시점 제약·디스조인트 재구성 때문에 🔶 **재확인 필요**로 하향.

**2-2. 버스트형 — 🔶 진행 중 · 미확정 (9/9 요건 추가)**

| 단계 | 시도 | 결과 | 판정 |
|---|---|---|---|
| 1 | 교수님 지시 이행: 상점별 KDE(밀도 상위 5%)로 버스트 구간 정의 | 사기율 13.9% ≈ 전체 평균(13.22%) | 실패 — 순수 시간 밀도는 정상적 인기 상승과 구분 안 됨(Fei et al. 2013이 지적한 문제와 일치) |
| 2 | 1단계 결과 + 평점조작 신호(극단평점 1/5점, 상점평균 대비 평점이탈) 결합 | 사기율 31%, 표본 2,623건 | 판별력은 확보했으나 표본 부족 |
| 3 | 시간축을 상점별 KDE에서 전역 윈도우(예: 7일 3건)로 완화 | — | 절충 시도. 다만 9/9 기준으로 보면 여전히 "절대 기준" 방향 |
| 4 | 완화된 시간 기준 + 평점 신호 결합 | 사기율 28.1%, 표본 19,077건 | 2단계 대비 표본 약 7배 확보 — **9/9 이전 최유력 후보였으나, 아래 9/9 신규 요건 미반영 상태라 재설계 필요** |

**9/9 신규 요건 (기존 4단계 후보를 대체해야 함)**:
- **동적(adaptive) 임계값**: 위 1~4단계 모두 전역/상점별 KDE든 결국 절대(또는 반절대) 기준이었음 — 교수님 지적은 **상점별 평소 리뷰 발생량 대비 상대적인 동적 기준**으로 만들 것. 구체적 수식은 9/9 시점 기준 **미확정**, 팀 내 후속 설계 필요.
- **시간 집중도 조건과 평점 이탈 조건을 독립적으로 각각 실험**할 것(AND 결합 금지) — 결합하면 개선이 시간 집중 때문인지 평점 이탈 때문인지 원인 분리 불가. 각각 단독 실험 + 결합 실험을 모두 비교.
- **"사기율이 높아졌다" ≠ "정의가 개선됐다"**: 임계값을 어떻게 잡느냐에 따라 사기 비율은 얼마든지 오르내릴 수 있음 — 위 표의 "31%", "28.1%" 같은 수치를 근거로 "정의를 잘했다"는 뉘앙스로 보고서에 쓰지 말 것.

**미확정 사유 — 확정 전 확인 필요한 항목 (9/7 항목 + 9/9 추가)**:
- 상점별 발생량 대비 동적 임계값의 구체적 산출 방식 설계 (9/9 신규).
- 시간 집중도 조건 vs 평점 이탈 조건을 분리해 독립적으로 각각 실험 (9/9 신규).
- 19,077건 층(4단계 후보)이 최종 데이터 범위(Phase 1-C, 2014년 한정) 적용 후에도 학습 가능한 규모로 남는지 재확인.
- 완화된 정의로 잡힌 사례 일부를 직접 확인해, 1단계에서 확인된 문제(정상 인기 상승 오염)가 재발하지 않는지 검증.

**2-3. 신규&버스트 교집합(혼합) — 🔶 배타적 재구성 필요 (9/9)**

- 기존(9/7) 방식: 신규계정형 ∩ 버스트형 겹침 허용(독립 라벨). **9/9 기준으로 변경**: 유형 간 라벨은 반드시 디스조인트해야 하므로, 겹치는 사례를 별도의 배타적 카테고리로 두거나(예: "저활동형이면서 버스트형인 경우"를 제3의 배타 클래스로 분리) 표본이 부족하면 "일반"으로 통합하는 방식으로 라벨링 로직을 재정리해야 함.
- 우선순위상 저활동형·버스트형이 먼저 확정된 뒤에 진행 — 이 항목은 나중.

**라벨 누수 방지**: 서브유형 정의에 쓰인 변수(리뷰 수, singleton 여부 등)가 조건 A의 수작업 피처에 그대로 들어가지 않도록, 해당 변수를 제외한 버전을 병행 준비.

## 판단 기준 — 언제 "MLP→GNN 개선폭(delta)"을 보고, 언제 "GNN 절대 성능"을 보는가

이 매트릭스 작업 중 반복적으로 나오는 선택 상황(그래프 구성, 피처 구성 등)마다 어느 기준으로 비교할지 헷갈릴 수 있어 원칙을 정리한다. **기준은 "그 대상이 무엇이냐"에 따라 갈린다.**

- **그 대상이 매트릭스에서 비교하려는 독립변수 자체라면 → delta(MLP→GNN 개선폭) 기준.** 이 연구의 RQ가 "구조 정보가 유형별로 얼마나 기여하는가"이므로, 절대 성능만 보면 "피처 자체가 원래 잘 맞혔다"와 "그래프가 실제로 기여했다"가 섞인다. 예: 조건 A의 피처 구성(review_16_only vs all_38)이 여기 해당 — 그룹 상수 피처(작성자/업체 수준)를 넣으면 MLP 절대 성능은 올라가지만, 이는 그래프의 기여가 아니라 피처 테이블에 그룹 정보가 새어 들어간 것에 가깝다. 유형별 구조 의존도 차이가 review_16_only에서만 뚜렷이 드러난 것이 이 기준을 따라야 하는 이유를 실증한다.
- **그 대상이 매트릭스 전체에 공통으로 깔리는 인프라(고정값)라면 → GNN 절대 성능 기준.** 다만 **9/9 갱신**: Phase 1의 그래프 구성은 더 이상 "A/B 공통 고정값 하나"로 조기 확정하지 않고 Phase 1-B의 7가지 조합을 유형별로 각각 실험하는 것으로 바뀌었으므로, 이 두 번째 기준(절대 성능으로 바닥판 확정)은 그래프 구성에는 더 이상 적용하지 않는다. 그래프 관계 조합 자체도 이제 delta(관계 추가 시너지) 기준으로 본다.

## 조건 정의 (열)

| 조건 | 그래프 구조 | 노드 피처 | 모델 |
|---|---|---|---|
| A. 구조/메타데이터 기반 | 사용 (Phase 1-B의 7가지 관계 조합을 유형별로 실험) | 수작업 표층 피처 (38차원, 아래 참고) | 바닐라 GNN(GCN/GraphSAGE) → PC-GNN → (여유 시) BWGNN |
| B. 하이브리드 | 사용 (A와 동일 관계 조합 실험) | 고차원 텍스트 임베딩, **상점 메타데이터는 별도로 추가**(아래 참고) | GNN |
| C. 텍스트 전용 | 미사용 | 텍스트 임베딩만 | MLP (non-GNN, 순수 베이스라인) |

**9/9 갱신 — 피처 추가 방식**:
- 조건 A의 38차원 피처는 기존 "review_16_only vs all_38" 이분 비교 대신, **피처를 성격별(메타 특성 / 활동 특성 / 리뷰 특성 등)로 카테고리화한 뒤 그룹 단위로 하나씩 단계적으로 추가**하며 관찰한다(어떤 피처 그룹이 가장 중요한지 끌어내기 위함). 카테고리 정의는 후속 문서화 필요.
- 조건 B에서 텍스트 임베딩과 상점 메타데이터는 **반드시 각각 독립적으로 추가**해 효과를 분리한다(동시 결합 금지) — 실험 순서상으로도 "바닐라 GNN(수작업 피처) → 텍스트 임베딩 추가 → 상점 메타데이터 추가"의 순서를 따른다.
- 텍스트 임베딩으로 인한 성능 개선은 (교수님 확답 기준) 차원 수 증가 효과가 아니라 의미(시맨틱) 정보 효과로 해석한다. 단, 유형에 따라 텍스트 임베딩이 효과가 없을 수 있으며 이 역시 "텍스트만으로는 못 잡아내는 사기 유형이 있다"는 유효한 파인딩으로 취급한다.

## 유형 정의 (행)

- **저활동형** (구 "신규계정형", 9/9 명칭·정의 개정): 해당 리뷰 작성 시점까지의 이력 기준, 작성자 전체 리뷰 수 ≤ 임계값(현재 3). 전체 데이터 기준으로 계산(표본 기준 계산 시 오탐 39.8% 확인됨). 이 기준으로 자르면 R-U-R 엣지가 없는 싱글턴 비율이 약 69% — Phase 1-B의 RSR/RTR 조합 실험으로 보완 여부 관찰.

## 공통 유의사항

- 셀마다 라벨 정의에 쓰인 변수(`singleton` 등)를 제외한 버전을 병행 보고해 라벨 누수를 점검한다.
- 사기율이 유형별로 크게 다르므로(3~26%) AUROC/AUPRC와 함께 베이스라인 대비 lift를 병기한다.
- Yelp 라벨은 "사기 확정"이 아니라 "니어 그라운드 트루스"임을 보고서 전반에서 일관되게 표현한다(9/9).
- 사기 비율의 상승/하강 자체를 "라벨 정의 개선"의 근거로 쓰지 않는다(9/9) — 임계값 조정만으로도 얼마든지 변동 가능.
- 유형 라벨은 디스조인트(배타적)해야 하며, 겹치는 경우를 독립 라벨로 중복 허용하지 않는다(9/9).
