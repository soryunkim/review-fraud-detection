# 관계 자체의 사기 신호 (오동진, 2026-09-22)

스크립트: `scripts/13_relation_label_signal.py`

성능 비교로는 버스트형 판단이 안 되므로, 모델 학습 없이 그래프와 라벨로 두 단계를 본다.
2014년 전체 리뷰를 쓰고, CI는 상점 단위 cluster bootstrap 300회로 구했다.

## 1단계: 관계에 정보가 있나 (`stage1.csv`)

각 리뷰의 과거 이웃 중 filtered 비율이 자기 라벨을 얼마나 가르는지 AUC로 잰다.

| R-T-R | 사기 리뷰의 이웃 사기 비율 | 정상 리뷰의 이웃 사기 비율 | AUC |
|---|---|---|---|
| 비저활동 · 버스트 | 0.330 | 0.153 | 0.684 [0.611, 0.734] |
| 비저활동 · 나머지 | 0.169 | 0.107 | 0.578 [0.564, 0.595] |
| 저활동 · 버스트 | 0.447 | 0.187 | 0.719 [0.683, 0.748] |
| 저활동 · 나머지 | 0.195 | 0.118 | 0.575 [0.562, 0.588] |

버스트 안에서는 사기 리뷰끼리 같은 시기 이웃으로 뭉쳐 있다. 평점이탈형은 R-S-R·R-T-R 모두 나머지 리뷰와 비슷하다.

## 2단계: 수작업 피처와 겹치나, 모델이 꺼낼 수 있나 (`stage2.csv`)

로지스틱 회귀, 1~9월 학습 / 10~12월 채점. 37개 대비 ΔPR-AUC를 잰다.
- `label` = 이웃 정답 라벨 비율을 더함 (상한, oracle)
- `pred` = 이웃의 37개 예측 점수 평균을 더함 (현실판)

| R-T-R, 버스트 리뷰 | label | pred |
|---|---|---|
| 비저활동 | +0.051 [+0.010, +0.090] | +0.004 [−0.008, +0.019] |
| 저활동 | +0.116 [+0.070, +0.164] | +0.016 [−0.007, +0.029] |

**해석**: 버스트에서 R-T-R의 신호는 37개 피처와 겹치지 않는다. 그런데 신호가 이웃의 라벨에 있고 피처에는 없어서, 이웃 피처를 모으는 GNN은 쓰지 못한다. GNN의 R-T-R 기여가 0 또는 음수였던 결과와 맞는다.

## 주의

1. `label`은 같은 달 이웃의 라벨을 쓰는 상한값이다. 예측 시점에 알 수 없는 정보이므로 "관계에 정보가 있다"는 근거로만 쓴다.
2. Yelp 필터가 몰린 리뷰를 한꺼번에 걸렀을 가능성이 있다. 그렇다면 뭉침은 사기꾼의 행동이 아니라 필터의 특성일 수 있고, 이 데이터로는 둘을 구분할 수 없다.
3. R-U-R의 `label` 값(+0.6 수준)은 필터 판정이 작성자 단위로 이루어진다는 뜻이다. 버스트 분석과는 관계없는 참고값이다.
