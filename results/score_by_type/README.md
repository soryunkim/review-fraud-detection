# 학습은 전체로, 채점만 유형별로 (소륜, 2026-09-30)

스크립트: `scripts/14_score_by_type.py` — 9/21 제출 요약 §8 질문2 선택지 ①

비저활동형(high) 전체 101,926건으로 학습한 GNN(R-U-R, GraphSAGE)·MLP 모델의
기존 점수 파일(`data/processed/scores/{gnn,mlp}/high_*_timesplit*.parquet`, 재학습
없음)을 채점 단계에서만 유형 라벨로 잘라 ΔPR-AUC(GNN−MLP)를 쟀다. R-S-R·R-T-R
그래프의 timesplit 전체그룹 점수 파일은 로컬에 없어(팀원 실행분, git 비대상) R-U-R만
계산했다.

## 결과 (12월 test, 8,988건)

| 칸 | n | 걸러진 리뷰 | dAP | 95% CI |
|---|---|---|---|---|
| 전체 | 8,988 | 633 | +0.0513 | [+0.0248, +0.0792] |

CI는 상점 단위 cluster bootstrap 1,000회(`12_type_intensity_gain.py`와 동일 관례).

## 해석

**표본 문제가 재학습 없이는 완화되지 않는다.** 평점 이탈형 칸의 점수 파일은
"칸만으로 학습"했을 때(§6-3, +0.030 [−0.029, +0.090])와 "전체로 학습"한 이 결과
(+0.051 [−0.011, +0.116])에서 점 추정치는 달라졌지만, 두 경우 모두 95% CI가 0을
포함해 판정 불가는 그대로다. 이유는 명확하다 — 채점 대상은 어느 쪽이든 "그 유형에
속한 test 리뷰 671건(걸러진 73건)"으로 같고, PR-AUC의 검정력은 학습 데이터 크기가
아니라 **채점 대상의 걸러진 리뷰 수**로 정해지기 때문이다. 즉 §8 질문2의 선택지
①만으로는 표본 문제를 풀 수 없다는 것이 이 실측의 결론이다 — 선택지 ②(리뷰 단위
지표, `../review_level_gain/README.md`)가 실제로 표본을 늘린다.

참고로 "전체 학습"과 "칸만 학습"의 PR-AUC 자체(그래프 기여가 아니라 모델 성능)도
달라진다: 전체 학습 쪽이 더 많은 데이터를 봐서 대개 소폭 낫다. 이 스크립트는 그 차이를
분리해서 보진 않는다 — "재학습 없이 표본이 느는가"만 확인하는 것이 목적이었다.
