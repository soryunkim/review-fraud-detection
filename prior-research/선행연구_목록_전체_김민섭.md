## Part 1. 사기 유형 룰베이스 라벨링 계획 (계획서 삽입용)

### 배경
교수님 코멘트: *"Yelp 데이터셋은 스팸/정상이라는 이분법 라벨만 준다. 그러니 '신규계정형', '버스트형' 같은 세부 유형은 우리가 직접 규칙(rule)을 만들어서 나눠야 하고, 그 규칙은 아무 근거 없이 만들면 안 되고 선행연구에서 가져와야 한다."*

### 어떤 논문이 어떤 유형의 근거가 되는가

| 사기 유형 | 근거 논문 | 이 논문이 제시하는 규칙 |
|---|---|---|
| **버스트형** | Fei et al. (2013) | 리뷰가 올라온 시간을 일정한 시간 구간(윈도우)으로 쪼갠 뒤, 같은 구간에 몰려서 리뷰를 남긴 사람들을 "버스트 그룹"으로 묶음 → 이 로직을 그대로 라벨링 규칙으로 사용 |
| **신규계정형** | Mukherjee et al. (2013) | 계정을 만들고 첫 리뷰까지 걸린 시간, 리뷰 작성 빈도, 평점이 극단적으로 치우친 정도 등 구체적인 수치 지표를 제시 → 이 지표에 기준값(threshold)을 정해서 "신규계정형" 라벨을 붙임 |
| **여러 유형이 겹칠 때 우선순위** | Rayana & Akoglu (2015) | 텍스트·시간·평점·네트워크 정보를 한꺼번에 종합해서 의심도를 매기는 방식 → 유형이 중복될 때 어떤 걸 우선할지 정하는 규칙 설계에 참고 |

### 계획서에 넣을 문장 (그대로 복사 가능)

> **사기 유형 하위 라벨링(Sub-labeling):** 확보한 데이터셋은 스팸/정상 이진 라벨만 제공하므로, 선행연구(Fei et al. 2013의 버스트 윈도우 탐지 기준, Mukherjee et al. 2013의 계정 행동 지표: 가입 후 첫 리뷰 시점, 리뷰 밀도, 평점 편차 등)에서 제시된 임계값 기반 규칙을 참조하여 리뷰/리뷰어를 신규계정형·버스트형 등 세부 유형으로 룰베이스 하위 라벨링을 직접 수행한다. 라벨링 기준의 타당성은 선행연구의 정의를 인용·근거로 제시한다.

#### ① Exploiting Burstiness in Reviews for Review Spammer Detection
**(Fei, Mukherjee, Liu, Hsu, Castellanos, Ghosh · 2013)**

> 한 줄 요약: 짧은 시간에 리뷰가 몰리는 "버스트" 현상을 이용해서 스패머를 잡아낸 원조 논문. 우리 팀 "버스트형" 라벨의 근거.

- **분류**: 구조/메타데이터 기반
- **인용 위치(예정)**: 방법론 (사기 유형 라벨링 규칙의 근거)
- **코드 공개**: N (공식 코드 없음, 방법론 설명 위주)

| 항목 | 내용 |
|---|---|
| Main Topic | 리뷰가 특정 시간대에 몰리는 현상(버스트)을 이용하면 스패머를 찾아낼 수 있을까? |
| How | 리뷰를 시간 구간으로 나눠서, 같은 구간에 몰린 리뷰어들을 네트워크로 연결한 뒤 신뢰전파(loopy belief propagation)로 스팸 여부 판단 |
| Data | 아마존 등 제품 리뷰 데이터 (버스트 구간 라벨링), 정확한 규모는 원문 재확인 필요 |
| Experimental Setups | 스패머 vs 정상 리뷰어 분류 문제로 두고, 기존 평점 기반 방법과 성능 비교 |
| Results | 버스트 기반 방법이 기존의 개별 리뷰어 행동 분석 방법보다 더 잘 찾아냄 |
| Significance | "버스트형"이라는 사기 유형 개념 자체를 처음 정립한 논문 — 우리 라벨링 규칙의 핵심 근거 |
| Discussion | 버스트가 진짜 인기 급증(정상)일 수도 있어서 오탐 가능성 있음 → 우리는 이걸 별도 유형으로 명확히 분리해서 다루면 이 한계를 보완할 수 있음 |

#### ② Spotting Opinion Spammers Using Behavioral Footprints
**(Mukherjee, Kumar, Liu, Wang, Hsu, Castellanos, Ghosh · 2013)**

> 한 줄 요약: 리뷰 텍스트는 아예 안 보고, 계정 행동 패턴 숫자만으로 스패머를 잡아냄. 우리 팀 "신규계정형" 라벨의 근거.

- **분류**: 구조/메타데이터 기반
- **인용 위치(예정)**: 방법론 (사기 유형 라벨링 규칙의 근거)
- **코드 공개**: N

| 항목 | 내용 |
|---|---|
| Main Topic | 리뷰 텍스트 없이, 행동 패턴만으로 스패머를 구분할 수 있을까? |
| How | 가입 후 첫 리뷰까지 걸린 시간, 평점이 얼마나 극단적인지, 리뷰 작성 빈도, 특정 업종에 몰아서 쓰는 정도 등 여러 "행동 지표"를 설계해서 점수화 |
| Data | Amazon.com 리뷰 데이터, 대규모 실사용자 기반 |
| Experimental Setups | 사람 평가자가 매긴 스패머 순위와 이 방법이 매긴 순위를 비교 |
| Results | 텍스트 없이 행동 지표만으로도 스패머를 정확히 찾아냄 → "행동 정보가 텍스트보다 강력한 신호일 수 있다"는 초기 근거 중 하나 |
| Significance | "신규계정형" 등 세부 유형을 정의할 수 있는 구체적인 기준(임계값)을 제공 — 우리 라벨링 규칙의 직접적 근거 |
| Discussion | 재현은 가능하지만 기준값(threshold)은 데이터셋마다 다시 맞춰야 함 → 우리는 Yelp 시카고 데이터에 맞게 재조정 필요 |

#### ③ Enhancing Graph Neural Network-based Fraud Detectors against Camouflaged Fraudsters (CARE-GNN)
**(Dou, Liu, Sun, Deng, Peng, Yu · 2020)**

> 한 줄 요약: 사기꾼이 정상인 척 위장할 때도 잘 잡아내는 GNN. 구조 기반 계열의 대표 모델이자, 우리 팀이 가장 먼저 재현 테스트할 후보.

- **분류**: 구조/메타데이터 기반
- **인용 위치(예정)**: 방법론 (구조 기반 대표 베이스라인)
- **코드 공개**: Y → github.com/YingtongDou/CARE-GNN (YelpChi·Amazon 데이터 포함)

| 항목 | 내용 |
|---|---|
| Main Topic | 사기꾼들이 정상 유저처럼 위장(camouflage)할 때도 GNN이 잘 탐지하게 하려면? |
| How | 라벨 정보를 활용한 유사도 측정 + 강화학습으로 "믿을만한 이웃"을 골라주는 선택기 + 관계 종류별로 따로 집계하는 방식을 결합 |
| Data | YelpChi (리뷰 스팸, 스팸 비율 약 14.5%), Amazon (리뷰어 사기) — 둘 다 공개 벤치마크 |
| Experimental Setups | 훈련 데이터 비율(1%~40%)을 바꿔가며 AUC/Recall로 다른 GNN들과 비교 |
| Results | 기존 GNN 및 다른 사기탐지 GNN보다 더 좋은 성능(당시 SOTA) |
| Significance | 구조/메타데이터 계열의 대표 베이스라인. 코드·데이터 다 공개돼 있어서 **2주 파일럿 테스트 최우선 후보** |
| Discussion | 텍스트 임베딩 없이, 미리 만들어진 32차원 피처만 사용 — "구조 기반 계열은 텍스트를 잘 안 쓴다"는 우리 문제의식을 대표하는 사례 |

#### ④ Rethinking Graph Neural Networks for Anomaly Detection (BWGNN)
**(Tang, Li, Gao, Li · 2022)**

> 한 줄 요약: 그래프의 "주파수" 관점에서 이상치를 찾아내는 방법. 구조 기반 계열 중에서도 spectral(주파수 필터링) 방식의 대표 사례.

- **분류**: 구조/메타데이터 기반
- **인용 위치(예정)**: 방법론 (구조 기반 대표 베이스라인, spectral 연산방식 사례)
- **코드 공개**: Y → github.com/squareRoot3/Rethinking-Anomaly-Detection

| 항목 | 내용 |
|---|---|
| Main Topic | 그래프에서 이상치가 "주파수(스펙트럼)" 관점에서 특별한 패턴을 보이는가? 이를 이용해 탐지 성능을 높일 수 있을까? |
| How | 이상치가 있으면 스펙트럼 에너지가 고주파 쪽으로 쏠리는 현상("우측 이동")을 발견하고, 이를 잡아내는 Beta Wavelet 기반 필터(BWGNN) 제안 |
| Data | YelpChi, Amazon, T-Finance, T-Social 등 4개 대형 벤치마크 |
| Experimental Setups | 훈련 비율(1%, 40% 등)별로 F1-macro, AUC를 CARE-GNN·PC-GNN 등과 비교 |
| Results | YelpChi 40% 훈련 기준 PC-GNN 대비 F1-macro +13.9%p, AUC +10.6%p 향상 |
| Significance | 구조 기반 계열 안에서도 "필터 방식(spectral)"이 다르면 성능 차이가 크게 난다는 걸 보여줌 — 우리가 정리한 "입력 피처 vs 연산 방식은 다른 축"이라는 구분의 실제 증거 |
| Discussion | 코드 공개돼 있어 재현 가능. 다만 이 논문도 텍스트는 안 씀 — "구조 기반 계열이 텍스트를 계속 배제해왔다"는 문제의식이 여기서도 재확인됨 |

#### ⑤ Finding Deceptive Opinion Spam by Any Stretch of the Imagination
**(Ott, Choi, Cardie, Hancock · 2011)**

> 한 줄 요약: 리뷰 글만 읽고 가짜인지 판단하는 고전 논문. 사람보다 훨씬 정확했음.

- **분류**: 텍스트 내용 기반
- **인용 위치(예정)**: 서론 (텍스트 기반 방법론의 고전적 출발점) / 방법론 (텍스트 피처 설계 참고)
- **코드 공개**: 데이터셋만 공개(Deceptive Opinion Spam Corpus), 코드는 여러 재구현 버전 존재

| 항목 | 내용 |
|---|---|
| Main Topic | 리뷰 텍스트만 보고 "일부러 속이려는" 가짜 리뷰를 구분할 수 있을까? |
| How | 세 가지 방식(단어 조합 패턴, 심리언어학적 특징(LIWC), 글의 성격 분석)을 비교, 최종적으로는 단어조합+LIWC 조합에 선형 SVM 적용 |
| Data | Mechanical Turk(크라우드소싱)로 사람이 직접 쓴 가짜 호텔 리뷰 400개 + TripAdvisor 실제 리뷰 400개 = 총 1,600개, 공개 데이터셋 |
| Experimental Setups | 5-fold 교차검증, 사람이 직접 판별한 정확도와 비교 |
| Results | 약 89~90% 정확도 — 사람이 판별했을 때(50%대, 거의 무작위 수준)보다 훨씬 높음 |
| Significance | "텍스트만 봐도 꽤 잘 찾아낼 수 있다"는 걸 실증한 고전 논문. 텍스트 계열 대표 베이스라인 후보 |
| Discussion | 크라우드소싱으로 만든 "가짜" 리뷰라 실제 사기 리뷰와 문체가 다를 수 있음 → 실제 Yelp 데이터에서도 잘 통하는지는 별도로 검증해봐야 함(우리 연구의 재현성 테스트 대상) |

#### ⑥ Collective Opinion Spam Detection: Bridging Review Networks and Metadata
**(Rayana & Akoglu · 2015)**

> 한 줄 요약: 텍스트+시간+평점+네트워크를 다 합쳐서 판단하는 초기 하이브리드 방법. 우리가 쓸 Yelp 데이터셋(시카고 등) 자체의 출처 논문이기도 함.

- **분류**: 하이브리드(그래프)
- **인용 위치(예정)**: 서론 (YelpZip/YelpNYC/YelpChi 데이터셋 출처) / 방법론 (다중 정보원 통합 방식 참고)
- **코드 공개**: Y (SpEagle 관련 구현 다수 공개)

| 항목 | 내용 |
|---|---|
| Main Topic | 텍스트·시간·평점·네트워크 관계를 하나로 합치면 스팸 리뷰·리뷰어·타겟 상품까지 동시에 잡아낼 수 있을까? |
| How | SpEagle — 리뷰·리뷰어·상품을 그래프로 놓고, 신뢰전파(loopy belief propagation)로 메타데이터·텍스트·관계 정보를 함께 전파. 라벨이 조금 있으면 반지도학습으로도 확장 가능 |
| Data | Yelp에서 필터링된(스팸) 리뷰와 추천된(정상) 리뷰로 구성된 실제 데이터 3종(시카고·뉴욕·자카르타 등). 원본은 비공개지만 이후 YelpChi/YelpZip/YelpNYC로 널리 재배포됨 |
| Experimental Setups | 텍스트만/네트워크만 쓰는 개별 방법들과 AP@k, NDCG 등으로 성능 비교 |
| Results | 개별 정보만 쓰는 방법보다 확실히 더 좋은 성능 — 통합 접근의 우수성 입증 |
| Significance | **우리 팀이 쓸 데이터셋(Yelp 계열)의 원조 논문**이자, "구조+텍스트를 합치는 게 낫다"는 걸 최초로 보여준 논문 |
| Discussion | 원본 데이터가 비공개라 완전한 재현은 어렵지만 파생 데이터셋(YelpZip 등)으로 대체 가능. 다만 "왜, 어떤 유형에서" 통합이 더 나은지는 설명하지 않음 — **이게 바로 우리 연구가 채우려는 빈틈** |

#### ⑦ Detecting LLM-Generated Spam Reviews by Integrating Language Model Embeddings and Graph Neural Network (FraudSquad)
**(Liu et al. · 2025)**

> 한 줄 요약: 최신 논문. 언어모델 임베딩 + GNN을 결합해서 AI가 쓴 정교한 가짜 리뷰까지 잡아냄. 우리 연구가 제안하는 "유형별 결합"의 최신 실증 사례.

- **분류**: 하이브리드(그래프)
- **인용 위치(예정)**: 방법론 (하이브리드 대표 베이스라인) / 결론 (향후 결합 방향 제시 근거)
- **코드 공개**: 확인 필요(논문 내 명시 여부 추가로 봐야 함)

| 항목 | 내용 |
|---|---|
| Main Topic | 텍스트 임베딩과 그래프 구조를 같이 쓰면, 특히 LLM이 만든 정교한 가짜 리뷰까지 잡아낼 수 있을까? |
| How | 언어모델(LM) 임베딩과 GNN을 통합한 FraudSquad 제안. 라벨이 1%만 있어도 학습되도록 설계 |
| Data | 자체 구축한 LLM 생성 스팸 리뷰 데이터셋 3종 + 기존 사람이 쓴 스팸 리뷰 데이터셋 2종 |
| Experimental Setups | 기존 GNN 기반 탐지기(PC-GNN 등)와 정밀도·재현율 비교 |
| Results | 기존 SOTA 대비 정밀도 최대 +44.22%p, 재현율 최대 +43.01%p 향상. 사람이 쓴 스팸 데이터셋에서도 개선 |
| Significance | 텍스트+구조 결합이 확실한 성능 이득을 낸다는 최신 실증 — 우리가 제안하는 "유형별로 정보를 다르게 결합하자"는 방향의 최신 근거 |
| Discussion | 2025년 최신 논문이라 재현 난이도·코드 공개 여부 추가 확인 필요. LLM이 쓴 리뷰라는 새로운 유형이 생기면서, 기존 사기 유형 분류 체계에도 시사점을 줌 |
